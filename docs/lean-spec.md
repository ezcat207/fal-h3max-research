# 精益创业 Spec：从 H3 Max 调研反推我们自己的商业假设

> 这是一份**活文档**。每完成一轮「调研 → 假设 → 验证 → 修正」循环，就回来改它。
> 目的：不是评价 FAL，而是**把 FAL 案例当作我们自己下一个商业产品的输入**，用精益创业的方式逐条验证。
> 版本：v0.1 ｜ 2026-09-04 ｜ 状态：**假设阶段（尚未验证）**

---

## 0. 精益循环怎么用（本文档的操作系统）

```
        ┌──────────────┐
        │  价值假设     │  用户真的想要它吗？
        │  商业假设     │  这门生意在经济上成立吗？
        └──────┬───────┘
               │ 拆成「最危险的待验证假设」
               ▼
   构建(Build) → 最小可验证实验(MVP/Smoke test)
               ▼
   测量(Measure) → 预先定义的成功指标 + 阈值
               ▼
   认知(Learn) → 坚持(persevere) 还是 转向(pivot)？
               └──────────► 回到顶部，修正假设
```

**规则**：
1. 每个假设都要写成**可证伪**的句子 + **一个数字阈值** + **一个最便宜的验证方式**。
2. 先验证**最危险**（错了整盘皆输）的假设，而不是最容易验证的。
3. 厂商/市场的营销数字（如 FAL 的 35×、#1）一律进「待验证假设」表，不进「事实」表。

## 1. 从 H3 Max 案例提炼的市场事实（作为我们的输入前提）

| # | 事实（已交叉验证） | 对我们的含义 |
|---|---|---|
| F1 | 视频模型正在**商品化**：开源权重（MiniMax H3、Wan）+ 多家托管（FAL/Replicate/Together） | **别赌「拥有更好的模型」**；模型不是护城河 |
| F2 | 价值链利润正从「模型层」流向**「推理/工作流层」和「分发/品牌层」** | 我们要占**工作流 + 分发**，而不是中间纯转售 |
| F3 | FAL 满价单条毛利 ~92%（基准），推理是**真高毛利**生意 | 若做应用层，**COGS 可控**；真正的成本是获客与留存 |
| F4 | 「快于实时」解锁了**交互/无限视频**新品类，但其**单元经济尚不成立**（需赞助） | 新品类是机会也是陷阱：**先算账再入场** |
| F5 | FAL 正在**向下游抢生意**（fal.live / Infinite Slop 与客户竞争） | **不能被单一后端锁定**；差异化不能只是「套壳」 |
| F6 | 当下**能赚钱的耐用玩法**是：faceless 内容工厂、UGC/效果广告、虚拟人/口播、混剪 | 我们的落点应在这几类里选一个有**独占分发或数据飞轮**的 |

## 2. 价值假设（Value Hypothesis）

> 价值假设 = 「用户在用了我们的产品后，真的获得了价值」这件事是否成立。

**VH-0（占位，待我们选定方向后具体化）**：
> 「对于 **【某类明确用户，如：跨境电商独立站卖家】**，
> 在 **【某个高频痛点，如：为每个 SKU 批量产出可投放的短视频广告】** 上，
> 我们用 **【基于快/便宜视频生成的某工作流】** 能让他们
> **【某可测量的价值，如：把单条可投广告的制作成本从 $X 降到 $Y、时间从 H 小时降到 M 分钟】**。」

**支撑证据（来自调研）**：玩法 1–4 已被验证有真实付费需求（Arcads/Creatify/Hedra 等已有营收）。
**风险**：这些赛道**已经拥挤**，价值假设的差异化必须来自「更窄的用户 + 独占的分发/数据」，而非「更好的生成」。

**最危险的价值假设（先验证这个）**：
> **DVH-1**：目标用户的痛点足够痛，痛到愿意为「省下的时间/提升的转化」付费——而不是满足于免费额度自己拼。

## 3. 商业假设（Business Hypothesis）

> 商业假设 = 「围绕这个价值，能建成一门单元经济为正、可增长的生意」。

**BH-1 单元经济**：
> LTV / CAC ≥ 3，且回收期 ≤ 12 个月。
> 其中 **COGS（生成成本）** 参考 H3 Max 口径：满价 5 秒片约 $0.03（基准）— $0.18（悲观）。定价必须**在 COGS 之上留出足够毛利覆盖 CAC**。

**BH-2 定价权**：
> 我们能对**结果/工作流**收费（按产出的商业价值），而不是被迫按「生成秒数」透明转售——否则毛利会被后端价格战压平。

**BH-3 抗锁定**：
> 后端可在 **≥2 个推理供应商 / 模型** 间切换，单一后端涨价/断供/变竞争对手时，切换成本 ≤ 2 周工程量。

**BH-4 分发**：
> 我们有一条**边际成本递减**的获客渠道（内容飞轮 / 社区 / 集成生态 / SEO），而不是纯付费投放——否则 CAC 会随规模上升吃掉 F3 的高毛利。

**最危险的商业假设（先验证这个）**：
> **DBH-1**：在这个赛道，**CAC 不会失控**。因为生成本身是商品化的，护城河若不在分发，获客会变成纯烧钱。

## 4. 待验证假设登记表（Riskiest Assumptions Board）

> 按「错了会死」的程度排序。每轮循环只挑 1–2 个最危险的验证。

| ID | 假设（可证伪句） | 类型 | 成功阈值 | 最便宜的验证方式 | 状态 |
|---|---|---|---|---|---|
| A1 | 目标用户愿意为「批量视频广告工作流」付费（≥$X/月） | 价值 | 10 个目标用户里 ≥3 个口头承诺付费 / 预付 | 15 个访谈 + 假门(fake door) 落地页收邮箱/预付 | ⬜ 未验证 |
| A2 | 该工作流能把用户的单条制作时间降到「值得付费」的程度 | 价值 | 时间下降 ≥70% 且用户主动说「会继续用」 | 手动 concierge MVP（我们人肉用 FAL API 帮 5 个用户做） | ⬜ |
| A3 | CAC 可控（有非付费获客渠道能起量） | 商业 | 单渠道 CAC ≤ 目标 LTV/3 | 一条内容/社区渠道跑 4 周看获客成本 | ⬜ |
| A4 | 生成质量在**我们这个具体场景**里够用（768p / slop 问题不致命） | 价值 | 目标用户对成片可用率 ≥60% | 用真实 brief 跑 50 条，让目标用户盲评 | ⬜ |
| A5 | 单元经济为正（定价 − COGS − 分摊获客 > 0） | 商业 | 毛利 ≥60%，回收期 ≤12 月 | 用 A4 的真实 COGS + A1 的定价建模 | ⬜ |
| A6 | 不被单一后端锁定（可切换） | 商业 | 后端抽象层 + 2 家供应商验证跑通 | 技术 spike：同一 prompt 走 FAL 和另一家 | ⬜ |
| A7 | 后端（FAL 等）向下抢生意**不会**直接吃掉我们（我们有独占层） | 商业 | 说清楚「FAL 自己做不了/不愿做」的那部分是什么 | 竞品/威胁分析，写一页纸 | ⬜ |

**厂商声明→待验证清单**（不当事实用）：FAL 的 35× 吞吐、15× 更快、「#1」画质、每次生成的 GPU 并行数——若我们的假设依赖这些，必须自测。

## 5. 本轮（Cycle 1）计划

- **本轮目标**：完成对 FAL/H3 Max 的市场与经济结构调研（← 已完成，见 `research.md`）。
- **产出**：market facts（§1）+ 初版假设（§2–4）。
- **认知（Learn）**：
  - 模型不是护城河（F1/F2）→ 我们把方向从「做模型/套壳」**转向**「做窄场景工作流 + 独占分发」。
  - 高毛利在推理层（F3），但那层已被 FAL 等占据且它在向下抢 → 我们**不做纯转售**，做**结果计费的应用/工作流**。
- **下一轮（Cycle 2）要验证的最危险假设**：**A1 + A3**（有没有人愿意付钱 + 获客烧不烧得起）。
- **下一轮的最便宜实验**：选定 1 个具体窄场景 → 做假门落地页 + 5 个 concierge MVP + 一条内容渠道跑 4 周。
